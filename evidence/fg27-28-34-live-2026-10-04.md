# Live recovery and dynamic-total evidence — 2026-10-04

All transactions below use fictional homework records. No credential, user ID, API key, or private chat identifier is included.

## FG-27 — delivery retry after failure

### Telegram

- Submitted S06 through the production website as a linked salesperson.
- The manager approved S06. The first Telegram API attempt returned HTTP 400 because the test destination was deliberately set to an invalid chat destination. The sale approval remained saved in Supabase and its delivery remained failed; no Telegram message was delivered on that first attempt.
- Relinked the authorized WDH bot account to the valid private destination, repaired only S06's queued recipient using the employee's current linked destination, and pressed the production manager **Retry** button.
- The job became `sent`. The WDH bot chat received the actual S06 approval notice. Repeating the retry did not create another S06 sale or another delivery row.

### Google Sheets

- E08 was saved through the production website, written to `Expenses!A9`, and affected the company result by €35.
- In Supabase, only the E08 Sheet outbox delivery status was set to `failed` as controlled fault injection (`last_error='Injected missing-copy recovery test'`). The existing Google Sheet row remained present; no deletion or real Google API outage occurred.
- Pressed the production manager **Retry** button. The same E08 job returned to `sent`; `Expenses!A9` still contained E08. The application did not append a second transaction row. This verifies retry processing and stable-row behavior; it does not claim a real provider outage or missing-row repair.

### Reproduction

1. Open the production dashboard and select the manager role.
2. Inspect Delivery queue before retry: E08 `sheet current` is failed with the injected error; after retry it is sent. For the earlier S06 Telegram test, inspect its failed job, restore the linked destination, then press Retry and verify sent.
3. Inspect `Expenses!A9` and the manager dashboard. The E08 row remains at the same position and the company result is €3,940 before and after retry.
4. Compare Supabase records by reference and delivery event; the retry updates the existing job and does not create another sale/expense/delivery.

## FG-34 — notification failure and retry
