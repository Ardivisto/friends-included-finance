## FG-11 — cent rounding and pending-sale exclusion

The manager approved the original proposal. The refreshed production dashboard showed S07 approved with the proposal and final split preserved at 50%/50%/0%, and earned pool €0.01. Dashboard values after approval were:

- Project A: income €2,500.05; commission expense €250.01; project result €2,050.04.
- Company: income €5,350.05; commission expense €535.01; company result €3,915.04.
- Earned commissions: Richard €140.00; Anastasia €180.01; Jean-Claude €215.00.

The extra cent was credited to Anastasia, visible as her earned total increasing by €0.01. S07 appears once in the manager's saved records and its Sheet delivery is sent. There was no Telegram recipient linked for this website-created sale.

2. Submit S07 with amount €0.05, Project A, and proposed split 50/50/0.
3. Select manager role. Before approval, verify S07 is pending and excluded from approved income and commission totals.
4. Approve S07 without changing the proposal. Refresh the manager view and verify the recorded final split, €0.01 pool, dashboard values above, one S07 record, and sent Sheet delivery.

## FG-12 — expense allocation decision, shared totals, and permission enforcement

Submitted E09 through Kevin's actual production website expense form: €25, category Other, proposed allocation Project A, description “Fictional overhead allocation check”. Before the allocation decision, live dashboard values were company result €3,915.00 and awaiting allocation €165.00.

Svetlana changed the final allocation to Company overhead and saved the decision. The manager view showed the original proposed Project A allocation and final Company overhead allocation preserved on E09, with both Sheet synchronization and Telegram allocation notification marked sent. After the decision, company result remained €3,915.00, company overhead increased by €25.00 to €220.00, and awaiting allocation returned to €140.00. Project totals were unchanged by changing the allocation destination.

A production request to the expense-allocation endpoint using the Kevin role and an attempted Project B allocation returned HTTP 403 with `Only Svetlana can allocate expenses.` The request did not change E09 or dashboard totals. An initial request to the deployment-specific protected alias returned Vercel HTTP 401 before reaching the application; the authorization test was repeated through the public production alias and yielded the application 403 above.

2. As manager, verify E09 is pending, its proposal is Project A, and awaiting allocation is €165.00.
3. Submit the production allocation request as Kevin for E09 to Project B; verify HTTP 403 and the response text above.
4. As manager, allocate E09 to Company overhead. Verify the original proposal, final decision, sent Sheet and Telegram statuses, and resulting totals above.
